# AirMe 編輯式方格 UI／UX 設計規格

> 日期：2026-07-14
> 狀態：已實作；Web 自動與瀏覽器驗證完成，實體 iOS／Android 待驗證
> 適用範圍：`apps/client` 的 Web、iOS 與 Android 前端

## 1. 目標

將 AirMe 整套前端改造成參考圖所示的鮮明編輯式方格風格，而不是只替首頁換色。Web、iOS 與 Android 繼續共用同一套 Expo Router 產品流程與元件；所有作用中的頁面、狀態與互動都使用一致的視覺系統。

本次只改前端 UI／UX 呈現，不改產品定位、資料契約、AI 流程、安全規則、裝置端儲存或 API 行為。

## 2. 核准的視覺方向

介面直接採用參考圖的完整視覺語言：

- 珊瑚紅、亮黃、青綠、天藍、奶油白與炭黑的高對比色票。
- 2–3 px 炭黑外框、4–6 px 無模糊錯位陰影與較方正的卡片輪廓。
- 厚重、緊湊、具有海報感的繁體中文標題；正文維持易讀的系統中文字體。
- 膠囊按鈕、膠囊狀態標籤、粗框輸入框與明確的按壓位移回饋。
- 奶油色方格背景、亮黃色點陣區塊與青綠斜線重點區塊。
- 不延續目前的簡約藍綠卡片風格，也不保留依系統切換的深色主題；所有平台以固定亮色主題呈現。

參考圖只作為視覺語言依據。AirMe 不複製其品牌、文案、插圖、商標或產品結構。

## 3. 設計系統與元件架構

### 3.1 全域設計 token

在既有 `apps/client/src/design/tokens.ts` 集中定義：

- 品牌色、背景色、文字色、風險色與各自的前景色。
- 3 px 標準外框與不同用途的硬陰影位移。
- 方正卡片、小圓角控制項與膠囊標籤三組圓角。
- 既有 spacing 尺度與跨平台中文字體階層。

所有作用中元件只從 token 取得設計值，避免頁面內散落近似色或各自定義陰影。

### 3.2 共用介面元件

優先重製既有共用元件，不建立平行的第二套 UI：

- `Card`：粗框、硬陰影、可選背景色與可選圖樣表面。
- `AppButton`：珊瑚紅、亮黃、青綠、白底與危險操作變體；按下時降低陰影並產生位移。
- `Chip`：粗框膠囊，選取狀態使用實色與可辨識文字，不只依賴顏色差異。
- `AppText`：加入海報式 display／section heading 層級，同時維持正文行高。
- `Screen`：提供奶油方格頁面背景、響應式留白與一致的內容寬度。
- `AppHeader`、`BottomNav`：共用相同品牌標記、外框、陰影和導覽狀態。

背景圖樣以跨平台 React Native 元件繪製或重複排列，不依賴只在 Web 生效的 CSS，確保 App 與 Web 的主要視覺一致。

## 4. 導覽與響應式行為

- 1440 px Web：顯示具有品牌標記與頁面入口的上方導覽；主要內容採 2–3 欄卡片網格。桌面不再同時顯示浮動底部導覽。
- 平板：保留較寬卡片與 2 欄區塊，導覽依可用寬度自動縮排。
- 手機、iOS、Android：使用固定底部導覽，維持拇指可達性；卡片改為單欄，局部資訊可使用 2 欄小方格。
- 所有斷點維持相同內容順序、功能與狀態，不產生 Web 專屬角色或另一套產品流程。

## 5. 各畫面設計

### 5.1 初次設定

- 使用珊瑚紅 eyebrow、厚重主標題和簡短隱私說明建立入口層級。
- 年齡層、敏感條件、通勤、活動與地點整理成有編號的方格步驟區塊。
- 每一區仍使用既有 `Chip` 與相同欄位，不新增個資收集。
- 完成按鈕使用亮黃主行動樣式；未完成必要欄位時仍保持清楚的 disabled 狀態。

### 5.2 今日首頁

- 第一視覺焦點仍為「你現在想做什麼」，不改成 AQI 儀表板。
- 桌面以大標題、環境摘要和活動輸入組成不對稱雙欄 Hero；手機以單欄依序呈現。
- AQI 卡使用青綠斜線或奶油方格重點表面，活動輸入卡使用白底粗框。
- DEMO／LIVE、來源、更新時間與重新整理功能保留，僅重做階層和樣式。
- 錯誤提示使用珊瑚紅警示卡，仍保留原訊息與關閉操作。

### 5.3 AI 行動卡

- 風險摘要成為最上方主卡，以風險色、粗框標籤和大標題呈現。
- 建議方案的時間、地點、強度與準備項目改為可掃讀的 Bento 方格。
- 「為什麼」、資料來源、安全提醒、限定追問和五秒回饋維持獨立卡片，避免混合資訊責任。
- 緊急、安全、資料不足與降級狀態使用各自的高對比表面；不以裝飾弱化警告文字。

### 5.4 活動紀錄

- 頁首使用海報式標題與資料最小化說明。
- 紀錄在桌面形成卡片網格，在手機維持單欄時間序列。
- 風險標籤、時間、活動摘要、地點與資料模式都有固定位置，便於快速比較。
- 空狀態使用完整卡片，不新增未實作的篩選、搜尋或圖表。

### 5.5 設定與資料

- 示範模式、個人設定摘要、隱私界線與資料清除各自成為獨立方格卡片。
- 一般設定使用青綠或亮黃重點；不可逆清除操作保留珊瑚紅／危險色，且仍需二次確認。
- 不新增帳號、雲端同步、通知或其他未在產品規格內的能力。

## 6. 狀態與資料流

本次不改資料流。頁面繼續從現有 `AppProvider` 取得 hydration、環境資料、推薦結果、追問、回饋、紀錄與設定狀態。

所有既有狀態都必須有新設計對應：

- 載入：保留可辨識的 loading label 與 activity indicator。
- 空資料：使用有標題、說明與下一步的方格卡。
- disabled：降低彩度和陰影，但文字仍保持可讀。
- API／資料錯誤：顯示原有安全訊息，不顯示 provider 原始錯誤。
- DEMO／LIVE／partial／stale：使用文字與外框狀態，不只以顏色區分。
- 醫療與緊急安全狀態：優先於一般裝飾，保留完整求助內容。

## 7. 可用性與無障礙

- 互動目標至少 44 × 44 pt。
- 鍵盤 focus 使用可見的高對比外框，Web 可完整以鍵盤操作。
- 色彩對比以正文可讀性為優先；狀態不得只靠色彩表達。
- 正文避免使用描邊、過窄字面或全大寫英文；海報式字體只用於短標題。
- 支援 `prefers-reduced-motion`；按壓回饋只使用短距離位移，不加入持續或眩暈動畫。
- 文字放大與窄螢幕時允許卡片增高、標籤換行，不裁切安全說明。

## 8. 實作邊界

本次會修改 `apps/client` 的設計 token、共用 UI 元件、導覽與五個作用中頁面及其產品元件。必要時新增一個跨平台圖樣背景元件。

本次不修改：

- `services/api`、`packages/contracts` 或任何資料 Schema。
- Azure、政府 API、環境變數、部署或 remote。
- 產品規格中的功能集合、AI 安全規則與醫療界線。
- 未被作用中路由使用的 Expo starter 範例元件，除非 lint 或 build 顯示它們阻礙本次變更。
- 參考圖本身；不將該圖或其品牌資產加入 repository。

- `npm run test --workspace airme`

視覺與操作驗證：

- 375 × 812 手機寬度完成初次設定、今日輸入、行動卡、追問、回饋、紀錄與設定流程。

- 1440 px Web 顯示桌面上方導覽與多欄方格，且不重複顯示底部導覽。
- 核心互動可用鍵盤完成，focus 清楚可見。

完成的判斷不是「色彩相近」，而是所有作用中畫面都共享同一套參考圖式視覺規則，Web 與 App 的資訊層級、互動狀態和導覽方式保持一致且可操作。
